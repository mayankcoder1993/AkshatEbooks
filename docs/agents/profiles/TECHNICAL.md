# Technical Book Profile

Use for programming, software, computing and engineering books.

## Required brief fields

Technology and version, supported environment, reader experience, setup assumptions, final capabilities, security scope and intentionally excluded topics.

## Source hierarchy

Prefer official documentation, specifications, standards, release notes and first-party engineering references. Confirm version-sensitive behavior in the named version. Community sources may clarify practice but should not override authoritative behavior.

## Teaching pattern

- Begin with the job to be done.
- Show a minimal working example.
- Show exact input, execution steps and output.
- Explain what changed in memory, state, files or the network when relevant.
- Introduce terminology after the reader sees its job.
- Include prediction, guided modification, bug diagnosis and independent practice.
- Use comparisons with other technologies only when they clarify the active topic.

## Verification

Run executable examples where practical. Keep commands, filenames and output visible. Test error examples as well as success examples. State platform or version differences. Never present implementation details as universal language rules.

## Safety

Flag destructive commands, credentials, privacy risks, insecure defaults and production-only concerns. Use placeholders rather than real secrets. Do not ask beginners to disable security controls merely to make an example work.
